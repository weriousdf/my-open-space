## 형식별로 잰 값

같은 장면(알갱이 3,489,576개)을 `@playcanvas/splat-transform` v3.4.2 로 네 형식에 써서 쟀습니다.

| 형식 | 파일 크기 | 알갱이 개수 | 알갱이당 바이트 |
|---|---|---|---|
| .ply | 195,416,619 B (195.4 MB / 186.4 MiB) | 3,489,576 | 56.00 |
| .compressed.ply | 56,815,381 B (56.8 MB / 54.2 MiB) | 3,489,576 | 16.28 |
| .sog | **16,668,463 B (16.7 MB / 15.9 MiB)** | 3,489,576 | **4.78** |
| .spz | 19,583,911 B (19.6 MB / 18.7 MiB) | 3,489,576 | 5.61 |

- 올린 것은 `.sog` 입니다. `.ply` 는 186.4 MiB 라 깃허브의 파일 하나 100 MiB 관문을 넘지 못합니다.
- `.ply` 의 알갱이당 68바이트가 아니라 56바이트인 까닭은, 이 도구가 쓰지 않는 법선 세 칸(`nx, ny, nz`)을 빼고 14칸만 적기 때문입니다. 노트북이 직접 쓴 `.ply` 는 법선 세 칸을 포함해 17칸, 68바이트였습니다.
- 네 형식 모두 구면 조화 0차만 있고 각도별 색 45칸은 없습니다. 학습을 걸지 않았으므로 채울 근거가 없습니다.

## 만든 방법

```
영상 19초 → 사진 여러 장 → 점 → 알갱이 3,489,576개 → .sog 15.9MiB → 이 주소
```

복원은 코랩 T4 에서 `facebook/map-anything-apache` (Apache-2.0) 로 돌렸습니다.
계산 능력 7.5 인 T4 에는 bf16 이 없어 `amp_dtype="fp16"` 으로 바꿔야 메모리가 넘치지 않습니다.

띄우는 페이지는 three.js 와 Spark 를 씁니다. `.sog` 의 Spark 안쪽 이름은 확장자와 달리 `pcsogszip` 이고,
`SparkRenderer` 를 장면에 넣지 않으면 오류 없이 화면만 까맣게 나옵니다.

| 파일 | 무엇 |
|---|---|
| `index.html` | 알갱이를 브라우저에 띄우는 페이지 |
| `scene.sog` | 알갱이 3,489,576개, 15.9 MiB |
| `shots/viewer.png` | 화면 갈무리 |
| `.nojekyll` | 깃허브가 파일 이름을 손대지 않게 하는 표시 |
